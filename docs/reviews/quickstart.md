# 本机启动设计审核

审核对象为 01b、现有 README 与部署手册、account 和 worker 命令、ready 路由及 SQLite 设置。当前人工流程依赖 Python、Node、字体和两套常驻进程，首次开户也不能在脚本重跑时覆盖。

| 方案或问题 | 走查结论 |
|---|---|
| 原生脚本串联安装 | 仍依赖宿主 Python/Node 版本和字体路径。保留给自管 Python 环境使用。 |
| 两个进程放在一个后台脚本 | 退出和报错要单独处理。采用一个镜像、两个 Compose 服务，先迁移、Web 健康后再启 worker。 |
| 新库与升级 | 复用 SQLite 持久卷、Django migrate 和 account；检查有无可用审核员后再引导开户。重建镜像不换数据库或会话密钥。启动器只在 up --wait 和开户成功后展示完成提示。 |
| 本地与生产 | 采用本机回环端口、容器非 root 用户、独立卷。宿主环境只传业务连接变量，避免因现有生产 PGDATABASE 或 PRESS_ENV 意外迁移生产库。 |
| 交付验证 | 在有 Docker 的 Linux runner 从源码构建并从用户入口运行，验证登录、保存素材、停机重启、worker 与端口。Windows 门面独立检查成功/失败控制流。 |

**单人设计审核通过，授权实施 01b。** 内容品质问题以当前实现、实际测量的指标及人工评估方法回答，本模块只改本机启动路径。
